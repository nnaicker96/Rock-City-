# Simple Projects and Tasks — Proposed Setup

This is a proposed starter model, not a configured live database.

## Projects

A project describes an outcome: for example, Planning Center rollout or an October campaign. Each project should have a clear purpose, current status and links to its working material.

Suggested fields: **Project, Ministry, Owner, Status, Target date, Next action, Files**. Leave unknown owners and dates blank rather than inventing assignments.

## Tasks

A task describes an action someone can finish. Suggested fields: **Task, Project, Owner, Due date, Status, Priority, Updates, Files**.

Proposed statuses: **Not started, In progress, Waiting, Done**. “Waiting” should include what or whom the task is waiting for. These names can be changed when Nikyle confirms the operating model.

## Updates

An update should say what changed, what happens next and whether anything is blocked. Keep the conversation beside the task where practical. A completion check should relate to the actual intended result, not only to whether someone clicked Done.

## What this import does

These pages describe the model. They do not create native Person properties, assign real members, send notifications, connect Planning Center, or build database relations. Configure those against the actual workspace when the task system is implemented.

The latest intent is church-wide administration, not a system restricted to Tech Rock.
