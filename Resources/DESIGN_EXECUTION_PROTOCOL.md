# Rock City — Design Execution Protocol
Version 1.0 • 21 October 2026 • Applies to new creative production and revisions

## Authority and precedence
1. Current explicit user instruction and latest approved task-specific design.
2. Actual uploaded source assets and current project brief.
3. 00_START_HERE.md, 02_WORKING_PREFERENCES.md, 03_HARD_CONSTRAINTS.md, 06_BRAND_CREATIVE_SYSTEM.md, relevant ministry, Kairos and current-context files.
4. Generic creative suggestions only for genuinely unspecified details.
Do not treat an illustrative reference, unapproved generated trial, or an assistant suggestion as an approved decision. If conflict remains, state it; do not silently resolve it.

## Required workflow — before artwork
1. Read the canonical GitHub start file and all relevant files; inspect actual reference artwork, not only descriptions. State honestly which files/assets are accessible.
2. Extract a task-specific constraint ledger with **LOCKED** (exact copy, protected assets, theological meaning, user-defined layout), **VARIABLE** (authorised choices), **PROHIBITED** (rejected treatments), and **UNRESOLVED** (only blockers). Do not ask about choices already established.
3. Define the actual depicted action and physical environment, who is present, where the viewer's attention should go, where text belongs, and how the image differs meaningfully from rejected trials.
4. Check composition against reference designs BEFORE generating. A location change with the same people-door-type composition is not a new concept. Do not impose a house-door scenario when user specifies doors in shops, offices or other places.
5. Generate the requested deliverable, not another unsolicited proposal. Use original uploaded artwork for reference/editing when available. Do not claim exact preservation from a recreation.

## Visual system
- ROCK | CITY | CHURCH lockup, Bebas Neue display style, clean readable supporting type.
- Five pillar colours: evangelism #D63D3D; worship #E8A93B; discipleship #3093BD; fellowship #3FA876; ministry #7B4DA0. Use selectively.
- Contemporary editorial, sophisticated texture, layered organic forms, meaningful depth, deliberate hierarchy and controlled saturation. No sepia haze, generic crest/shield, stock-template look, arbitrary icons, invented slogans, decorative filler, distorted or misspelled text.
- Do not make every image use every motif. Preserve real-person likeness where requested. Use actual Dome/surroundings rather than inventing landmarks when the Dome is depicted.
- Distinguish *style reference* from *required repeated composition*. Variety is allowed without breaking brand continuity.

## After generation — mandatory audit
Check: (a) exact wording/spelling and references; (b) actual user-specified scenario and door function; (c) reference-style fidelity; (d) human action and believable setting; (e) composition differs from rejected attempts; (f) brand/theology; (g) no unauthorised additions; (h) readable mobile and print hierarchy.
If an output fails, do not describe it as compliant. Revise when possible; report remaining limitations honestly. A generative-image tool cannot guarantee perfect text, character consistency or placement; for precise final typography, use deterministic layout tools and source artwork.
Do not assume quality audit happened merely because flaws can be identified after the user points them out.

## Revision discipline
Change only what was requested. Keep all other approved elements unchanged. Never turn a correction into a new creative direction. Avoid performative apologies and assurances in place of corrective work.

## Asset custody
Keep approved reference assets in an explicit, versioned asset library with filenames, status (reference/trial/approved/rejected), source and permission notes. A text-only GitHub context does not itself preserve generated image binaries. Do not claim assets were uploaded or archived until verified.
